# ADR-7: theme-presets 定位为外部覆盖面

## 状态

Accepted（2026-08-03）

## 语境

原重构计划（`docs/theme-refactor-plan.md` §6）规划数据包 `@soybeanjs/theme-presets` 为"JSON 单一数据源"，其中任务 8 要求**引擎改从数据包取数**——即数据包拥有核心数据的唯一真相源，引擎内置数据迁出。

P0 引擎（`@soybeanjs/theme`）已落地：内置 core-template + 派生引擎 + `createTheme({ preset })` 覆盖能力。在此背景下重新审视数据包定位时发现：

- 引擎的内置模板以"模板函数"形式存在（`createBaseCore(p)` 等），与 JSON 数据是两种表达；若迁出，需先把模板摊平成 9×10 键字面量数据，工程量大且收益存疑；
- 引擎的 preset 覆盖能力（ADR-5：核心显式 + 算法派生 + 自定义覆盖兜底）已经为"外部数据影响主题"提供了完整入口；
- 真实需求是**提供内置之外的预设方案**（社区/变体/修改起点），而非把数据搬出引擎。

## 决策

`@soybeanjs/theme-presets` 定位为**外部覆盖面**：

- 数据包发布一组预设（preset），每个预设是引擎 `CustomThemeColorPreset` 实例，通过 `createTheme({ preset })` 覆盖内置；
- **引擎保留内置基线**（core-template + 派生规则），不迁移数据、不消费数据包（ADR-2"JSON 单一数据源"不再适用于核心数据）；
- 数据包 JSON 源仅对**数据包自身**是单一数据源（JSON → 生成 TS 产物），不声称对引擎核心数据拥有所有权；
- 数据包与引擎解耦：运行时零依赖，仅 devDep `@soybeanjs/theme`（复用类型）。

## 后果

**积极：**

- 引擎自洽：内置可独立工作，数据包是纯增量；
- 覆盖链路清晰：内置派生 → 数据包 preset → 用户 inline preset，优先级一致；
- 数据包可独立发版，不牵动引擎。

**消极/代价：**

- 内置数据与数据包官方复刻存在"双份等值数据"（基线等值性质兜底，测试保证一致性）；
- 与 ADR-2 表述存在张力：ADR-2"JSON 单一数据源"现收窄为"数据包内部的单一数据源"。

## 备选方案

1. **唯一数据源**（原 §6 任务 8）：引擎改从数据包取数。否决——模板函数摊平成本高、收益存疑、破坏引擎自洽。
2. **双源并存**：引擎内置 + 数据包平行存在，不宣称任何数据所有权。折中——与本次决策区别在于是否把"官方复刻"作为一等公民纳入数据包（本次纳入）。
