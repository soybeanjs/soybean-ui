# Upgrade Guide: v0.30.0 → v0.40.0

v0.40.0 is a consolidation release: the peripheral packages are retired, the headless layer finally stops injecting styles, and the context helpers are renamed with cleaner semantics. This guide lists every breaking change with a migration path.

## 1. Peripheral packages removed

`@soybeanjs/ui-x`, `@soybeanjs/admin` and `@soybeanjs/chart` are no longer published. They were all released up to `0.30.0`, so if you depend on any of them, pin the old version or migrate as follows.

| Package            | Status                                                                                                                                                             | Where the capability goes                                                                                                                                                                                                   |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `@soybeanjs/ui-x`  | Removed (20 `Sx*` AI components)                                                                                                                                   | Re-implemented inside `@soybeanjs/headless` + `@soybeanjs/ui` under the standard `S` prefix — see the AI roadmap. Not available yet in `v0.40.0-beta.1`.                                                                    |
| `@soybeanjs/admin` | Removed (skeleton only — no shipped components)                                                                                                                    | Returns as an in-core **shell domain** (`SLayoutShell`, `SPageHeader`, …) — see the shell roadmap. Nothing to migrate.                                                                                                      |
| `@soybeanjs/chart` | Removed (`SChartContainer`, `SChartTooltipContent`, `SChartLegendContent`, `SChartStyle`, `chartColors`, `chartThemes`, `componentToString`, `buildChartColorCss`) | Charts are intentionally **not** part of the core library. The docs site builds its chart demos directly on [TanStack Charts](https://tanstack.com/charts); copy `apps/docs/src/examples/chart/` if you want the same look. |

```bash
# Remove the retired packages
pnpm remove @soybeanjs/ui-x @soybeanjs/admin @soybeanjs/chart
```

```diff
- import { SxBubble, SxSender } from '@soybeanjs/ui-x';
- import { SChartContainer } from '@soybeanjs/chart';
```

If you are not ready to drop them, keep the last published versions pinned:

```json
{
  "dependencies": {
    "@soybeanjs/ui-x": "0.30.0",
    "@soybeanjs/chart": "0.30.0"
  }
}
```

## 2. headless: `RovingFocusGroup` / `RovingFocusItem` components removed

The two SFC primitives are gone from `@soybeanjs/headless` (root export, `./roving-focus` sub-path, and the `Headless.*` namespace). The behaviour now ships as composables, so you own the rendered element:

```diff
- <RovingFocusGroup orientation="horizontal" :loop="true">
-   <RovingFocusItem v-for="tab in tabs" :key="tab" as-child>
-     <button>{{ tab }}</button>
-   </RovingFocusItem>
- </RovingFocusGroup>
+ <script setup lang="ts">
+ import { toContext } from '@soybeanjs/headless/shared';
+ import { useRovingFocusGroup, useRovingFocusGroupItem } from '@soybeanjs/headless/composables';
+
+ const { setContainerElement, groupProps } = useRovingFocusGroup(
+   toContext({ orientation: 'horizontal', loop: true })
+ );
+ </script>
+
+ <template>
+   <div :ref="setContainerElement" v-bind="groupProps">
+     <button v-for="tab in tabs" :key="tab" v-bind="useRovingFocusGroupItem().itemProps">
+       {{ tab }}
+     </button>
+   </div>
+ </template>
```

`useRovingFocusGroup` returns `{ setContainerElement, groupProps, getOrderedItems }` and `useRovingFocusGroupItem` returns `{ setItemElement, itemProps }`. Options are reactive (`ToContext` shape), so build them from props with `toContext(props, [...])`; `itemProps` already carries `tabindex`, the collection attribute, orientation data attributes and the key handlers.

## 3. headless: context helpers renamed with new semantics

```diff
- import type { PropsToContext } from '@soybeanjs/headless/types';
- import { transformPropsToContext } from '@soybeanjs/headless/shared';
+ import type { ToContext } from '@soybeanjs/headless/types';
+ import { fromContext, toContext } from '@soybeanjs/headless/shared';
```

The rename is mechanical, but `toContext` also changed behaviour: `transformPropsToContext` **invoked** function-valued props (`typeof v === 'function' ? v() : v`), while `toContext` stores values as-is, so a function stays a function inside the context.

```ts
// Before: a `renderIcon: () => VNode` prop arrived as the VNode.
// After: it arrives as the function itself.
const context = toContext(props, ['renderIcon']);
context.renderIcon.value(); // call it where it is consumed
```

`fromContext(context, keys)` is the new counterpart: it snapshots a `toContext` map back into plain values, and tolerates a nullish context (useful in `defu` fallback chains).

## 4. headless: `ConfigProviderContext` is now plain values

The context type changed from a computed-per-key map to a readonly snapshot of the props:

```diff
- export interface ConfigProviderContext
-   extends PropsToContext<Omit<ConfigProviderProps, 'iconRender'>>,
-     Pick<ConfigProviderProps, 'iconRender'> {}
+ export type ConfigProviderContext = Readonly<ConfigProviderProps>;
```

If you consumed the context directly, drop the `.value` accessors:

```diff
- const context = useConfigProvider();
- const dir = computed(() => context?.dir?.value ?? 'ltr');
+ const context = useConfigProvider();
+ const dir = computed(() => context?.dir ?? 'ltr');
```

The provider now uses a shared injection key (`Symbol.for('ConfigProvider')`), so a duplicated `@soybeanjs/headless` copy in the module graph no longer breaks the lookup. Direction resolution also gained a step: an explicit `dir` → `ConfigProvider` `dir` → **direction derived from `locale`** → `ltr`.

## 5. headless: no more injected global classes

`SConfigProvider` used to inject a `<style>` tag with helper classes, and several headless parts hard-coded them. Both are gone — headless components are now genuinely style-free:

| Removed class                         | Replacement                               |
| ------------------------------------- | ----------------------------------------- |
| `soybean-headless-scrollbar-hidden`   | `scrollbar-none` (from the UnoCSS preset) |
| `soybean-headless-overflow-y-hidden`  | `overflow-y-hidden`                       |
| `soybean-headless-transition-all-150` | `transition-all duration-150`             |
| `soybean-headless-opacity-0`          | `opacity-0`                               |
| `soybean-headless-scale-0`            | `scale-0`                                 |
| `soybean-headless-sr-only`            | `sr-only`                                 |

The styled wrappers already apply the equivalents (for example `SScrollArea`'s viewport uses `scrollbar-none`), so most users see no change. If you use **headless primitives directly** and relied on the injected CSS, add the classes yourself:

```diff
- <ScrollAreaViewport class="soybean-headless-scrollbar-hidden">
+ <ScrollAreaViewport class="scrollbar-none">
```

Scrollbars are now hidden by a `scrollbar-none` utility shipped from `@soybeanjs/ui-uno` (`presetScrollbar`), which is part of `presetUiUnocss()` by default. If you consume headless without the preset, provide your own rule.

## 6. ui: `STable` no longer rounds by default

```diff
- <STable :data="rows" />          {/* was rounded */}
+ <STable :data="rows" rounded />  {/* opt back in */}
```

`rounded` now defaults to `false`, matching the other surface components where rounding is opt-in.

## 7. `@soybeanjs/ui-uno`: animation preset replaced

`unocss-preset-animations` is no longer a dependency; the preset is now built in and exported directly:

```diff
- import UnocssPresetAnimations from 'unocss-preset-animations';
- export default defineConfig({ presets: [presetUiUnocss(), UnocssPresetAnimations()] });
+ import { presetAnimations, presetScrollbar } from '@soybeanjs/ui-uno';
+ export default defineConfig({ presets: [presetUiUnocss()] }); // both already included
```

`presetUiUnocss()` keeps the same signature but gained pass-through options — `wind3`, `animations`, `scrollbar`, `webFonts`, `preflights` — and now also exports `buildGlobalCss`, `buildThemeColors` and `resolveWind3Dark`. A new `presetScrollbar` (which provides `scrollbar-none`, see section 5) is included by default. The `UiUnocssOptions` / `SbeanPresetOptions` types are still exported, so existing configs keep working.

## 8. Dependency cleanup (usually invisible)

- `@nuxt/kit` and `@nuxt/schema` are no longer `peerDependencies` of `@soybeanjs/headless`; the Nuxt module wiring was localised.
- Eleven runtime dependencies were inlined or dropped from `@soybeanjs/headless` (`@soybeanjs/hooks`, `@soybeanjs/utils`, `defu`, `klona`, `fuse.js`, `ohash`, `aria-hidden`, `@floating-ui/utils`, `@vueuse/shared`, `@dnd-kit/helpers`, `embla-carousel-reactive-utils`). If your app imported any of them **without declaring them** (relying on hoisting), add them to your own `package.json`.
- Contributor-side only: `packages/_shared` was renamed to `packages/shared` and switched to source distribution (`#shared/*` sub-path imports).

## What you gain

- **Popper rebuilt in place.** The positioning primitives gained `PopperTrigger`, `PopperPortal`, `PopperSub` / `PopperSubTrigger`, `PopperCompact`, delay groups and `useVirtualPointReference`, all under the existing `Popper*` names — no import changes for the old root/anchor/positioner/popup/arrow parts.
- **New navigation components**: `SNavMenu`, `SSplitNav`, `STreeNav` (plus their headless counterparts).
- **Flash-free persisted theme**: `createThemeInitScript({ injectCss: true })` replays the derived CSS from `THEME_CSS_STORAGE_KEY` before first paint.
- **Router-aware links**: `SConfigProvider` gained `linkComponent`, so every `SLink` / `SButtonLink` can render through `RouterLink` / `NuxtLink` without per-call props.

## Checklist

1. `pnpm remove @soybeanjs/ui-x @soybeanjs/admin @soybeanjs/chart` (or pin to `0.30.0`).
2. Rename `PropsToContext` → `ToContext` and `transformPropsToContext` → `toContext`; review function-valued context keys.
3. Replace `RovingFocusGroup` / `RovingFocusItem` usage with the composables.
4. Drop `.value` accessors on `ConfigProviderContext` consumers.
5. If you use headless primitives directly, replace the `soybean-headless-*` classes.
6. Add `rounded` to `STable` where the rounded look is expected.
7. Remove `unocss-preset-animations` from your UnoCSS config.
8. Declare any previously hoisted transitive dependency you imported directly.
